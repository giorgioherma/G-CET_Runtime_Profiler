# Shared static location registry and quest-start wake audit — 2026-10-16

**Status: audited / architecture accepted as a development target; NOT shipped, not a deployed source optimization.** Base is the actual user-supplied `EXTENDED DORMANCY(2).zip` live CET folder (142 mod directories, 1,631 Lua source files). Preserve user's requirement: one common fixed-location data service in 0-Engine, loaded once when the owning mod source and game session are ready; quest systems only wake on original first interaction or another verified activation condition. Do not mistake merely generated journal entries or map waypoints for started quests. Native B/C savings must be measured separately.

## Design decision

Separate **data**, **discovery**, **activation**, and **native subscriber lifecycle**:

1. **Owner-authored source of truth.** Keep literal/static coordinates in their owning Lua/JSON/mod pack. Each source-proven Resolver adapter *registers* normalized `{owner, sourceId, sourceFingerprint, anchorId, x, y, z, radius, kind, transformSpace}` exactly once with a namespaced 0-Engine `StaticAnchors` service on source init/session readiness. Cache plain Lua numbers and fixed metadata; do not retain game entities, native Vector4 userdata, mappin handles, mutable quest facts, mod runtime status, dynamic camera/actor/player positions or editor workspots as immutable data. No separate hardcoded master coordinates that could drift from a mod update.
2. **One shared registry and spatial index.** Deduplicate by owner/sourceId/anchorId, validate finite 3D position/radius, fail closed on duplicate IDs with conflicting coordinates. Index coarse world cells (e.g. 256 m) and expose `GetAnchor` / `QueryNearby` / diagnostics, preserving owner's transform and authoritative interaction radius. One shared player-position provider and bounded proximity worker can wake candidate owners; no per-mod polling loops on an identical fixed-layout array. Indexing is a *design* until implemented and profiled; avoid falsely claiming zero additional native cost.
3. **Register-once lifecycle.** Static source data loaded at CET/module init or first game-ready session, not re-parsed every frame. Retain immutable anchors across character/save reloads if source and provider epoch are unchanged. Reset **session-dependent** player state, native handles, entity references, available quests, timers, per-save progress and subscriptions on session load/end. Mod reload, source fingerprint change, JSON/editor save, track selection/update and any runtime point-pack replacement must invalidate that owner's registry version. An owner's delayed registration is permitted; do not assume 0-Engine loaded before all other mods.
4. **First-interaction activation, not waypoints.** A map pin or journal entry being present is never enough. Each quest has a source-proven start signal: author interaction UI/choice, native prompt, quest fact transition, phone/SMS/shard, manual hotkey, prerequisite completion, or mod API as applicable. Shared proximity discovery is **not** an automatic quest-start event. Subscribe while near enough to leave all original first-interaction code responsive; when genuinely active, restore all original tick/dialogue/cutscene/spawn/presentation/cleanup lanes immediately. Preserve activation and error-recovery wake from remote triggers while far away.
5. **Conservative native C.** Pausing an individual 0-Engine subscriber or adding a shared `ObserveAfter` router does not itself stop the shared native-to-Lua hook. Only label C-stage completed if a verified native hook filter/re-arm or demonstrable native crossing reduction exists. Any central proximity worker's own dispatch, source proof and wake latency count toward net cost. Never conflate a cache hit with saved callback allocations or a quest becoming dormant.

## Integrated A/B/C + Lua allocator dormancy — mandatory correction

**User decision, 2026-10-16:** A registry without per-mod execution dormancy is NOT the finished optimization. The cache must let the Resolver suppress each approved author's far-away work **across four separate cost layers**. The goal is to remove redundant per-mod polling and temporary allocations, not just trade a coordinate lookup for a cached coordinate. A shared worker has a cost of its own and net savings require measurement.

**Existing runtime to extend, not duplicate:** Live 0-Engine already computes a single player position in `init.lua:266-288`, passes it to both `modules/Proximity.lua` and `modules/SpatialHash.lua`, and dispatches adopted `onUpdate`/`onDraw` clients through one central emitter. `SpatialHash.RegisterSpatialSet` already has poll callbacks, entry rebuild and per-set grid, but its `Update` creates `local nowActive = {}` at line 275 every polling cycle, and `Proximity.Update` scans each registered zone in `pairs(zones)` with a frame throttle. Do not layer another independent player-position reader or second global spatial service over these. Extend existing 0-Engine with one multi-owner static-anchor index and an opt-in, allocation-bounded **wake gate**. If a separate module is used, it must reuse these stock state/index/lifecycle services and avoid a second scan.

### Four independently evidenced savings lanes

| Stage | What must stop when a source-proven location-only mod is far away | Honest completion evidence |
|---|---|---|
| **A — Lua and LuaJIT allocator** | The mod's `onUpdate`/`onDraw` bodies, recurring coordinates/distance loops, quest-state tables/snapshots, transient `Vector4`/lists/closure creation, and own location poll jobs *if none have an independent far-away duty*. The central index must reuse preallocated cell/entry state or epoch-stamped flags; onEnter/onExit only when transitions occur, not on every poll. | Callback executions and per-frame LuaJIT positive growth / allocation requests / GC object births decrease after accounting for the shared engine service. |
| **B — Lua → native** | Per-mod `Game.GetPlayer`, `GetWorldPosition`, `GetQuestsSystem`, mappin/journal/proximity/actor lookups, native vector construction and other reads that are only for idle location discovery. 0-Engine already reads the player position once during its frame state update; one shared read is preferable to N repeats. | Relevant native getter invocation counts decrease while quest/editor/scene and remote wake reads needed for correctness remain. |
| **C — native → Lua dispatch** | For adopted frame listeners, pause/unsubscribe **per-mod** listener via existing `GCETFrameListeners`/`Engine.MakeEventRegistrar` so 0-Engine's shared frame hook remains one native crossing. For action/observer clients, deactivate a source-proven subscriber if an independent UI/spatial/quest wake exists. Native `Observe`/`ObserveAfter` direct hooks need phase-preserving lower-level capability before claiming true hook removal. | Per-mod native callback registrations/invocations decline or are retired; explicitly separate shared global native hook still running from per-mod dispatch saved. Merely returning early in Lua does not pass. |
| **Shared worker tax** | Avoid new per-mod timers, per-scan `nowActive={}` churn, cloned coordinate tables and per-candidate closures. Use squared distances, cell-indexed candidates, reusable enter/exit state and change-only notifications. Budget refresh distance/cadence against speed, fast travel and actual trigger geometry. | 0-Engine added CPU, allocator and native reads remain less than avoided owner costs, using comparable scenarios; no zero-cost assumption. |

### Per-mod gate state and invariant

Use explicit states `UNAVAILABLE` (invalid/unready engine, conservative author fallback), `FAR_DORMANT`, `NEAR_ARMED`, `ACTIVE`, `RECOVERING`. The *gate* is a source-proven owner-specific adapter, not a globally assumed rule: entering a discovery/wake radius changes FAR_DORMANT→NEAR_ARMED and reattaches the original input/prompt/location handler **before** the first interaction. The actual author start interaction, remote quest fact, SMS, other mission handoff or API event changes NEAR_ARMED/FAR_DORMANT→ACTIVE. Active quests keep running even when the player leaves the cached location. Quest completion/reset may move ACTIVE→FAR_DORMANT only after every pending payout/cleanup/streamed actor/diagnostic wake obligation is discharged. `RECOVERING` stays active through save-load, interrupted teleport and controller/session repair. A map marker, created journal entry or proximity alone **never starts** a quest.

**Strict source proof before suspension:** A candidate can fully sleep only if its audited code has no independent remote writer, no world-load/cleanup/resume obligation requiring the sleeping callback, no pending Cron/job/animation, and no dynamic start anchors. Otherwise move only the location-discovery subsection behind the shared near gate while keeping its cheap independent wake path. If state proof fails, missing 0-Engine API is `REQUIRES_ENGINE_EXTENSION`, not `IMPOSSIBLE` or a safety-free forced sleep. Require proof for every author state writer and `onInit`/`onUpdate`/`onDraw`/`onShutdown` subscription, alternate save, hot reload and 0-Engine-absent fallback.

**Source ownership / no duplicate data:** Never maintain two independent editable coordinate tables; cache normalized immutable numeric anchors from the author's already loaded data. Register with owner/source fingerprint and epoch; author source change/editor save/map switch/foreign points pack replacement must invalidate. Resident data and geometry may survive saves, but object handles, fact snapshots, quest progress and active region state may not. If the data is already a Lua array loaded once (e.g. Tunnel layout), avoid cloning the full array; index only the small approved start/interaction anchors.

**Proposed Resolver integration:** Each existing mod-owned semantic rule gains an optional `LocationGate` stage with independently verified source postconditions; source passes compose pristine→all stages **in one run** and upgrade old partial stages without rollback. The generated author source preserves exactly its registered original callbacks and captures their dispatch handle for `Pause/Resume` only if the shared source and wake graph prove coverage. With no 0-Engine service, or when player position is not trustworthy, fail open to original author logic. Do not manufacture keybinds or move quest-activation authority into 0-Engine. Dynamic/remote-only components remain live if needed.

**Acceptance tests before claiming completion:** synthetic and real original/partially optimized/fully optimized source for each mod; duplicate/shared anchor registration; near-radius exit/reentry; movement/fast travel; delayed startup; different saves and session reinitialization; quest offered-but-not-started; remote phone/SMS/quest activation; in-progress leaving the region; completion/abort/recovery; editor and point-pack invalidation; native hook phase/fallback; GC allocation of the central index under sparse and dense anchor sets. Profile baseline vs composed gate at *both* per-mod and aggregate 0-Engine level. Game validation is still required; no performance gain from this design has yet been measured.

## Hotscenes and DriveAerialVehicle native C follow-through

- **hotscenes**: `hotscenes_native_ui.lua:4156-4179` has `ObserveAfter('PlayerPuppet','OnAction',...)`. It requires **isShowtime**, **isMainMenu OR isSelectionList**, at least one active instance, a live shard-controller and **REPEAT** navigation action. The action observer is needed for UI navigation, not automatically for video playback with closed UI. Route via a phase-faithful after-observer and synchronize wake from all original menu/shard lifecycle writers. A new shared observer alone is not native C elimination; verify hook-level suspension or report only subscriber consolidation.
- **DriveAerialVehicle**: `Modules/core.lua:426-488` native Observe forwards **every** action only when `current_situation` is Waiting or InVehicle; after configured consumption exceptions, it calls `StorePlayerAction`. `Modules/event.lua:237+` transitions include Normal → Landing → **Waiting before mounting** → InVehicle, so a rule 'sleep whenever not inside an aerial vehicle' would break pre-boarding controls. Exact wake is the original `Event:SetSituation`, game/session resets, mount/dismount, and any late AV spawn/recovery. A phase-accurate wildcard subscriber with SetActive may be gated to Waiting/InVehicle. Preserve all actions and original Consume semantics.

## Build order and acceptance contract

1. Extend **existing 0-Engine Proximity/SpatialHash/FrameListeners** with an allocation-bounded, owner-versioned shared anchor registry **and gated wake interface** (no new duplicate native player read). Add state-transition-driven author listener `Pause/Resume` capability as an integrated, explicitly opt-in A/B/C service. Test source ownership/invalidations, nonallocating polling, external triggers, fail-open fallback and all lifecycle transitions. The service can land independently, but **register-only is a component, not a completed optimization**.
2. Adopt two **simple static authors first** (StreetGamesPoker and VehicleRepairGarages) and one transform-backed source (Tunnel Rescue). For each, prove **both registered immutable anchors and suppression of safe out-of-range Lua/allocator/native-read paths**, plus gated native listener suspension *only where independent wake is complete*. Prove pristine→full composition and staged→full upgrade in one Resolver pass; measure the central worker tax and validate all author start interactions, remote wake/cleanup and game behavior.
3. Extend with shared proximity discovery and per-mod activation proofs (Ziggy and CyberTrials next). Model remote activation, active-state transition, stale saved session, fast travel, movement at speed, proximity hysteresis, first interaction, external/quest starts. If wake is uncertain, leave native frame dispatch live and optimize B only.
4. Add versioned adapters for GigCore pack registration, Joytoys offers, ELM editor, Hidden Packages selected map and redscript-provided illegal mechanic locations. Never freeze dynamic author/third-party data for the entire process lifespan.
5. Profile before/after **native dispatch calls**, **Lua callback invocations**, **LuaJIT allocations**, **0-Engine spatial worker cost**, **GC steps** and **CapFrameX p95/p99/hitches**. CI source tests plus game behavior required. No claimed savings until measurements.

**Explicit non-goals:** auto-start every quest when the player enters a radius; treat a generated journal entry or waypoint as started; replace mods' positions with centrally guessed values; cache dynamic game handles across saves; rewrite every one of thousands of track/checkpoint points into persistent Lua copies; promise full native C elimination via a Lua early return.
