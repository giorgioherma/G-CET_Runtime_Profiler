## Generic structure lessons, not mod-specific hardcoding

1. Coordinates can originate in fixed Lua tables, multiline records, author JSON, special `.map` files, and external cross-mod interaction project JSON. The scanner must distinguish a source/data provider from a wake consumer.
2. Different geometric predicates are **not interchangeable**: vehicle XYZ zones, fixed 1m XYZ start triggers, Hidden Packages' 100m XY square, and nativeInteractions choice ranges all have distinct lifecycle and latency requirements. A broad native NEAR gate can wake the author's exact predicate but must never be substituted for it without equivalence proof.
3. A candidate is worth admitting only if the Resolver actually **retires recurring author location work**. R4's ELM workspot data publication by itself is **NO_GAIN**.
4. Mixed wake is normal. Preserve independent phone, quest, input, sonar, vehicle recovery, spawning/despawning, active gameplay and save/session work while extracting strictly the location lane.
5. Native lease ownership is stage-dependent. `FAR_DORMANT` requiring location wake still has an **armed** native anchor. Irrelevant or completed owner locations **disarm** their native anchors. No independent per-mod poller may be added.
6. Original-author and already-R4-optimized versions differ: the generic transform must be reversible, postcondition-tested, idempotent and stage-aware. Source drift fails closed.

**Verification boundary:** R4 was a Lua-only experimental overlay, **not** proof of game-tested native wake retirement. The incoming ZIPs are developer fixtures, not evidence of what is currently installed. The remaining six originals still require structural comparison as generic patterns, but source coverage is now complete.
