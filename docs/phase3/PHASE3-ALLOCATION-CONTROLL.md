## Verified CET architecture — why early return is insufficient

CET `Scripting.cpp` holds one `sol::state` LuaJIT VM; per-mod `LuaSandbox` environments are separate namespaces, **not separate GCs/heaps**. `ScriptStore::TriggerOnUpdate` calls every mod `ScriptContext::TriggerOnUpdate`, which invokes the stored callback. CET `FunctionOverride.cpp` captures REDengine RTTI hook chains and **builds `sol::object` arguments via `Scripting::ToLua` before Lua observers run**. Therefore native-hook ingress / argument conversion can allocate before an empty/no-op Lua subscriber returns. The C++ shared hook stays as long as it is installed, even if a 0-Engine child subscription is paused; arbitrary CET `Observe`/Override lacks a generic subscriber unsubscribe guarantee. `0-Engine.MakeEventRegistrar`, `FrameListeners` Pause/Resume and `SubscribeAction` can stop the *client* and/or route through one shared host, not necessarily suppress the entire native hook for other clients. Upstream source: [CET Scripting.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/Scripting.cpp), [ScriptStore.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/ScriptStore.cpp), [ScriptContext.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/ScriptContext.cpp), [FunctionOverride.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/FunctionOverride.cpp).

Terminology:
- **Callback work (CPU)**, **positive LuaJIT allocator bytes and request count**, **GC object/string births**, **net heap growth**, **retained objects/references**, **GC phase/collector time**, and **native pre-dispatch marshalling** are different measurements. Never label per-mod allocation requests as its owned heap size or garbage live bytes.
- A callback's `~50 allocation operations per frame` yields ~2,250/s at 45 FPS and ~3,000/s at 60 FPS. Small allocation size is **not** grounds to ignore frequent creation; rank **ops/s and bytes/s independently**. Measure operations/call and sizes by bracket, short-lived samples, source producer and state.
- A GC hitch overlapping a callback does not prove that callback caused the garbage; shared 0-Engine callback costs are not automatically its own source costs. Native owner zero remains unassigned unless exact context/source proof exists.
- Early-return ≠ physically paused shared job ≠ unsubscribed CET hook ≠ deallocated mod state. Already allocated objects remain reachable while references exist.

## Desired wake mechanisms — cheapest *when correct*, with relative cost/coverage

| Candidate | Inactive overhead | When preferable | Caveat / proof obligation |
|---|---|---|---|
| Existing author state-transition or CET keybind signal | Usually no extra frame poll | TPP toggle, scene/quest stage, interaction, UI start-stop, queue transitions | Verify all writers, load/reload/failure paths; use existing input only; queued cleanup remains awake |
| Event-driven native location crossing / authoritative game signal | Event-specific, possibly no Lua frame work | Static jumps, stations, garages, apartments, collectible/quest vicinity | Must support teleport/fast travel, moving objects, save reload, far→near and native fallback; hook ingress may itself marshal |
| Shared 0-Engine action filter or already existing observer | Centralized listener, per-event overhead | Exact source-proven named actions, UI navigation | The shared native RTTI hook may still execute and marshal for every event; filter early native-side **only if safe** |
| One-shot due-time or cancelable scheduler | O(reactivation), not every rendered frame | Quest deadline, queued job, delayed cleanup | Re-arm on all relevant transitions; no lost deadline/resume |
| Coarse zone/state polling (adaptive cadence) | Periodic, >0 | Incomplete event graph with explicit latency budget | Avoid new allocations/native getters; dynamically sleep longer while irrelevant, fast near activation |
| Always-on EveryFrame wake probe | Highest continuous polling overhead | Only true camera/movement/ADS/active scene-frame requirements | Inactive feature should not run per frame solely to check whether it is still inactive |

Design **two distinct owners**: (1) a proven cheap **wake source**, (2) the often-expensive **active worker**. Wake sources must be small: read cached primitive/bit/state, avoid tables/strings/closures/per-frame closures/native handles, skip redundant RTTI marshalling where the current shared route makes that provable; no work queue creation if state unchanged. Workers physically detach only after *all* owed author cleanup; resume before author input/action/scene transition becomes observable. Keep fallbacks fail-open **with diagnostics** when the proof or runtime is unavailable.

If no complete event wake, use *measured* bounded coarse probe (not invented guarantee). Keep the cheapest proof-carrying wake and cancel higher-rate job when idle.
4. **Investigate instrumentation (capture-only).** Add experimental native/managed low-overhead state-transition ledger: per scheduler job owner/calls/ops/bytes (nested attribution with unscoped work separated), actual pause/resume/detach transitions, observer activation & native class/method/chain fanout, pre-marshalling byte/ops envelope, source allocation size histograms and bounded object lifetime/escape samples. Sampling must declare coverage, avoid allocation in hot hooks, preserve existing CSV metrics; exact DLL/PDB build pair, startup safety, capture-off and on overhead gates. No false per-mod *retained heap* claim.
5. **Repair only existing generators when proven.** Pristine one-pass, partial/live upgrade, idempotent, source drift and fallback tests. Do not conflate simpler early return with full native unsubscribe; do not break original logic to achieve zero counts.

## Reproducible controlled pressure tests

- **Equipment/provenance:** same game/CET native Profiler DLL hash, current original-source baseline, identical Resolver overlay and JSON, same save/graphics/fps cap/0-Engine config, same in-game clock/weather if relevant, CMB absent, FPS/GC metrics capture ON for comparisons and capture OFF for overhead controls. - **Idle baseline (120 s):** stationary safe indoor save; no menus/interaction/TPP. Record first 20 s warmup separately; steady 100 s should show zero inactive eligible mod jobs and allocations, except documented essential wake probes.
- **Repeatable traversal (120 s):** fixed waypoints and speed (walk/run), no quest changes; distance-to-candidate zone bins and native location gate events. Record hits/bytes per wake probe.
- **Active/deactivate (90+90 s):** activate one mod feature (e.g. poker interaction, trial UI, TPP toggle + ADS, mechanic station), then leave and wait for author cleanup; measure wake latency, return to physically zero recurring work and preserve behavior.
- **Default Phase 3 combat stress — `COMBAT-POLICE-60` (60 s):** user's apartment-area police fight, one combat-only capture, same save/gear/stack/settings, F11 start/stop. Maintain sustained police combat for ~60 seconds, record wanted-state/spawn deviations; inspect scheduler jobs/0-Engine residual/native hooks, CPU, allocation operations and bytes, GC-object births and frametimes separately. Use the linked benchmark file as the authority. This supersedes the generic 90-second suggestion.
- **Lifecycle (save/load, teleport, UI open/close, vehicle enter/exit):** prove no missed wake after stage changes and no stranded pending cleanup; 2 repeats each.

If a minimal independent probe is indispensable, document exact cadence, ops/call, 95p wake latency and why no cheaper signal is complete. Active state must preserve responsiveness, ordering and author functionality. Whole-game allocation rate, collector costs and CapFrameX remain metrics, not proxy approval of an individual wake.
