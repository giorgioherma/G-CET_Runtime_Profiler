> **Successor to PHASE 2 — DORMANCY EXTENDED.** Phase 2 attacked excess Lua callback execution by generic frame/action consolidation, external workers, native location gating, staged cadence and extended dormancy. Phase 3 completes that work by targeting **unnecessary allocation frequency and size at every layer**, especially apparently dormant callbacks, shared scheduler tasks and native-to-Lua marshalling. **Status 2026-10-29: Phase 3 instrumentation and selected dormancy fixes are implemented and gameplay-measured; the program is NOT complete stack-wide.** This is a source optimization phase; **G-GC Controller** is a separate, approved-but-not-implemented collector-assistance design, *downstream of eliminating avoidable producers*.

## Mandatory Phase 3 interpretation contract — READ BEFORE ANALYZING CAPTURES

**This section is normative and overrides stale dated implementation/status descriptions further down.** The goal is not primarily better average FPS or fewer milliseconds of Lua callback CPU. Phase 3's objective is to **reduce frequency and size of unnecessary allocations at their true producers, relieve the single shared CET LuaJIT collector, reduce native-to-Lua marshalling/wrapper creation when safe, and eliminate *visible gameplay stutter* (particularly repeated and severe frametime spikes).** Optimize source producers first; G-GC Controller/collector assistance remains a separate downstream concept, not a substitute.

**Non-negotiable decision order for every capture and before/after report:**

1. **Frame delivery and spikes FIRST:** Report P99/P99.9 where available, hitch frames/episodes per minute at *identical* thresholds, >50/>100ms frame counts, worst frame and outlier circumstances. Distinguish reduced *ordinary tail* from an unchanged/worse catastrophic maximum. Take the user's felt stutter improvement seriously as qualitative gameplay evidence; do not silently turn it into a numerical claim.
2. **GC pressure SECOND:** Report collector work ms/s, incremental/atomic/sweep spikes, collection cycles, object/string births, net growth where captured. Compare matched windows; note GC/callback overlap and never assign a collector pause or retained heap to a named mod because it occurred inside that mod's callback envelope.
3. **Allocator producers THIRD:** Report positive LuaJIT allocation **requests/s and bytes/s**, ops/call, frequency and size histogram, job-level exclusive/inclusive and unscoped owner-zero counts. Prioritize large repeated producers (including tiny per-frame allocations); a physically paused recurring job whose captured calls/ops drop to zero is direct producer-elimination evidence.
4. **Native-to-Lua boundary FOURTH:** Report source-proven native dispatch frequency, argument conversion, repeated `sol::object`/next-wrapper materialization and callback fanout, with method-stage provenance. Such stage counters may overlap other totals: **never sum them with owner-zero/GC/job totals**. A Lua no-op/paused downstream subscriber does not prove native observer removal.
5. **Average FPS and CPU LAST:** Include them as useful outcomes, **never** use them as the lead success metric or a substitute for evidence about stutters, GC, allocator frequency and native ingress.

**Controlled A/B acceptance is not a documentation scavenger hunt.** `COMBAT-POLICE-60` is the user-selected one-key F10, synchronized CET+CapFrameX, 60-second sustained apartment-area police-combat protocol. **The user explicitly confirmed the 2026-10-28→2026-10-29 tests were controlled A/B.** Respect that confirmation: absent written save/position/gear details in a ZIP are **not evidence that the user failed to control those settings**. Record missing provenance as `NOT_RECORDED` rather than reclassifying the entire test `uncontrolled`. Genuine observed scenario/stack/config deviations should be identified and qualified explicitly; do not invent an all-else-equal attribution when more than one optimization changed. **One qualifying capture per configuration is the default; repeats are optional to quantify stochastic variability**, not grounds to invalidate an otherwise controlled test.

**Three evidence gates must not be conflated:**
- **Direct per-mod Phase 3 dormancy:** proven stopped *targeted job execution* (0 actual calls and 0 measured positive allocation requests) during source-proven inactive state, bounded wake cost, completion of owed cleanup, and user-confirmed gameplay behavior. This does **not** require an isolated FPS improvement, nor does it establish removal of an independent native hook.
- **Controlled scenario outcome:** compare matched `COMBAT-POLICE-60` captures for P99/hitches, GC, allocator pressure, native handoff and FPS. Configuration-level changes are measured; individual-mod contribution requires a separate isolation experiment. Missing a particular old telemetry field means `NOT_MEASURED` for **that field**, not that the test is invalid.
- **Mechanism/causality:** lowering allocation production can reduce shared GC pressure and improve frametime in a **nonlinear** way, potentially crossing a practical pressure threshold. This is an **important source-grounded hypothesis consistent with reported gameplay**; claim a *measured* GC pressure reduction/threshold only when matched collector/allocator metrics actually show it. A single 94ms GC overlap or owner-zero window does not assign source blame.

**Mandatory language:** Say “user-confirmed controlled A/B,” “physical targeted-job pause proven,” “P99 improved but worst frame worsened” when true. Never say “not a controlled A/B” merely because some metadata was not collected; never say “FPS improved, therefore GC relief is proven”; never say “all native callbacks stopped” when only a child job was paused. The 2026-10-29 acceptance checkpoint and residual hitch/GC/native handoff measurements are recorded in [LATEST-WORK](../LATEST-WORK.md) and the [standard benchmark](COMBAT-POLICE-60-BASELINE.md).

## Verified CET architecture — why early return is insufficient

CET `Scripting.cpp` holds one `sol::state` LuaJIT VM; per-mod `LuaSandbox` environments are separate namespaces, **not separate GCs/heaps**. `ScriptStore::TriggerOnUpdate` calls every mod `ScriptContext::TriggerOnUpdate`, which invokes the stored callback. CET `FunctionOverride.cpp` captures REDengine RTTI hook chains and **builds `sol::object` arguments via `Scripting::ToLua` before Lua observers run**. Therefore native-hook ingress / argument conversion can allocate before an empty/no-op Lua subscriber returns. The C++ shared hook stays as long as it is installed, even if a 0-Engine child subscription is paused; arbitrary CET `Observe`/Override lacks a generic subscriber unsubscribe guarantee. `0-Engine.MakeEventRegistrar`, `FrameListeners` Pause/Resume and `SubscribeAction` can stop the *client* and/or route through one shared host, not necessarily suppress the entire native hook for other clients. Upstream source: [CET Scripting.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/Scripting.cpp), [ScriptStore.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/ScriptStore.cpp), [ScriptContext.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/ScriptContext.cpp), [FunctionOverride.cpp](https://github.com/maximegmd/CyberEngineTweaks/blob/master/src/scripting/FunctionOverride.cpp).

Terminology:
- **Callback work (CPU)**, **positive LuaJIT allocator bytes and request count**, **GC object/string births**, **net heap growth**, **retained objects/references**, **GC phase/collector time**, and **native pre-dispatch marshalling** are different measurements. Never label per-mod allocation requests as its owned heap size or garbage live bytes.
- A callback's `~50 allocation operations per frame` yields ~2,250/s at 45 FPS and ~3,000/s at 60 FPS. Small allocation size is **not** grounds to ignore frequent creation; rank **ops/s and bytes/s independently**. Measure operations/call and sizes by bracket, short-lived samples, source producer and state.
- A GC hitch overlapping a callback does not prove that callback caused the garbage; shared 0-Engine callback costs are not automatically its own source costs. Native owner zero remains unassigned unless exact context/source proof exists.
- Early-return ≠ physically paused shared job ≠ unsubscribed CET hook ≠ deallocated mod state. Already allocated objects remain reachable while references exist.

## Desired wake mechanisms — cheapest *when correct*, with relative cost/coverage

| Candidate | Inactive overhead | When preferable | Caveat / proof obligation |
|---|---|---|---|
| Existing author state-transition or CET keybind signal | Usually no extra frame poll | TPP toggle, scene/quest stage, interaction, UI start-stop, queue transitions | Verify all writers, load/reload/failure paths; use existing input only; queued cleanup remains awake |
| Event-driven native location crossing / authoritative game signal | Event-specific, possibly no Lua frame work | Static jumps, stations, garages, apartments, collectible/quest vicinity | Must support teleport/fast travel, moving objects, save reload, far→near and native fallback; hook ingress may itself marshal |
| Shared 0-Engine action filter or already existing observer | Centralized listener, per-event overhead | Exact source-proven named actions, UI navigation | The shared native RTTI hook may still execute and marshal for every event; filter early native-side **only if safe** |
| One-shot due-time or cancelable scheduler | O(reactivation), not every rendered frame | Quest deadline, queued job, delayed cleanup | Re-arm on all relevant transitions; no lost deadline/resume |
| Coarse zone/state polling (adaptive cadence) | Periodic, >0 | Incomplete event graph with explicit latency budget | Avoid new allocations/native getters; dynamically sleep longer while irrelevant, fast near activation |
| Always-on EveryFrame wake probe | Highest continuous polling overhead | Only true camera/movement/ADS/active scene-frame requirements | Inactive feature should not run per frame solely to check whether it is still inactive |

Design **two distinct owners**: (1) a proven cheap **wake source**, (2) the often-expensive **active worker**. Wake sources must be small: read cached primitive/bit/state, avoid tables/strings/closures/per-frame closures/native handles, skip redundant RTTI marshalling where the current shared route makes that provable; no work queue creation if state unchanged. Workers physically detach only after *all* owed author cleanup; resume before author input/action/scene transition becomes observable. Keep fallbacks fail-open **with diagnostics** when the proof or runtime is unavailable.
