## Decision: Dedra-owned gameplay + one shared 0-Engine scheduling clock

**DO NOT** merge Dedra gameplay into ITP; author explicitly supports standalone operation. **DO NOT** use `GetMod` at file-load, register native CET `onUpdate` in `onInit`/`NextTick`, or call `FrameListeners.MakeRegistrar` during `onInit`: its `__gcetEnsureUpdate()` may call CET `registerForEvent`, which is precisely the hazardous lifecycle class observed in prior crashes. **DO NOT** solve this with a duplicate dispatcher, second scheduled runtime, or corrective semantic.

Use the existing, canonical `0-Engine/modules/G-CET/Scheduler.lua`. In the source-proven fixed 0-Engine runtime, `FixedZeroEngineRuntime.EnsureNamespacedSchedule` **adopts the stock file-load** `registerForEvent("onUpdate")` by inserting `Engine.__gcetScheduleDriver` into that author callback; it does **not** install another native callback when activated. On Dedra's `onInit` only, resolve `GetMod("0-Engine")` (allowed by CET upgrade guide); in the existing `ModPasses/DedraThirdPersonCombatAddon.cs` generator install a **single source-owned external coordinator** `GCET_Semantic/dedra_camera_wake.lua` that subscribes to the existing scheduler and existing event buses. The module init thin bridge owns config, PlayerPuppet attach and shutdown callbacks exactly once; the worker owns scheduling, wake/cadence and diagnostics. Never move all of Dedra's gameplay logic into ITP or the 0-Engine source.

The original `Dedra.step(dt)` / `dedraStep(dt)` remains authoritative for active gameplay (including camera takeover, NPC animation wrappers, weapon family, aim, head restoration, REDscript state and cleanup). `ctx.dt` is supplied to full-rate active execution, `ctx.elapsed` to a due timed maintenance execution. **Never call the author step twice in one tick**; after any mode change ensure elapsed accounting and preserved ordering. ITP event wakes only set state/activate a scheduled lane; they do NOT execute game/native writes reentrantly from the event callback.

## Cadence and wake

| Mode | Source proof | Execution | Rationale |
|---|---|---|---|
| **ACTIVE** | ITP user requests TPP, camera mode transition, combat takeover, pending ADS/ease-out/plane/head/arm/stand-in cleanup, unresolved player/session work, or any uncertain state | **ONE** `Schedule.EveryFrame` lane; run unchanged author step every game frame | Original animation/camera responsiveness and source-owned cleanup |
| **QUIET-FPP** | ITP public API is present and trustworthy, user TPP request false, mode first, no transition; **AND** all Dedra-owned cleanup debts are settled, REDscript state known and player lifecycle valid | Pause the active frame job; run original author reconciliation via ONE `Schedule.Every(0.25s)` lane initially | The author already has a 0.25s `HeldFamily` poll and a 0.5s `DedraTpcLink:State` poll. 0.25 s is the conservative initial bound; 0.5/1 s not approved until Core source and gameplay prove it. No unconditional per-frame Dedra callback; four due calls/s only |
| **NO-PLAYER/SESSION END** | Author player invalidation/session end, verified cleanup and no owed native player work | Pause both runtime lanes; keep only event subscriptions and author shutdown cleanup | Avoid game-object access in menu/save transitions |
| **UNKNOWN / PARTIAL** | Missing/rejected ITP wake/proof or unpredictable state | Fail OPEN to original full-rate author behavior *on existing adopted scheduler*; never silently suppress functionality | Required for custom ITP variants and non-proven cleanup |
| **NO VERIFIED 0-ENGINE** | No verified 0-Engine integration at Resolver generation time | Emit/preserve the source author's **original file-load CET onUpdate** and independent Dedra callbacks, not a late retrofit | Stack-independent original behavior; no new native hook at runtime |

Important: initial QUIET-FPP is low-frequency, **NOT zero-work fully dormant** because Dedra Core state can change independently. Only Core source-proven change notifications could safely replace the 0.25s verification clock with event-only sleep. Do not claim physical cancellation of Core work if the timer still runs. No need for native player-position/location cache: this is perspective/animation/weapon-state work.

**Shared wake sources without adding an expensive global observer:**
- ITP public `events.on` with exact current `perspectiveChanged`, `overrideChanged`, `transitionStart`, `transitionEnd`, `sessionStart`, `sessionEnd`; snapshot public perspective immediately upon bind to catch events emitted before binding. The existing ITP API is read-only; do not modify its proxy or overwrite exported events.
- 0-Engine's existing `Subscribe` events `AimStateChanged`, `WeaponStateChanged`, `UpperBodyStateChanged` (emitted by existing `BlackboardCache2.Init(Events)`), `CombatStateChanged`, `PlayerReady`, `PlayerInvalidated`. They reuse the host's already existing player/blackboard routing. Verify all signal production, payload and session reset in generated output; no extra native RTTI observer solely for these fields.
- Dedra's own native-settings callbacks `dedraSetCombatTpp`, `dedraSetAnims`, existing `PlayerPuppet.OnGameAttached`, and `onShutdown`, signalled by source-owned thin bridge. Do not duplicate its original hooks.
- Periodic QUIET-FPP tick catches `DedraTpcLink:State` (add-on-owned) / `DedraTpcLink:HeldFamily` changes and missed event delivery. Source audit of the exact uploaded REDscript shows `DedraTpcLink` does NOT publish a direct event for `State` or `HeldFamily`: do **not** claim full event-only dormancy. `DedraCoreStateSystem.RegisterFactListener` is available, and `StateRevision` changes on registered module, active fact and scene acquire/release, but **NOT on weapon family/aim changes**; existing 0-Engine blackboard subscriptions are still necessary. Only if a valid game-script listener can be proven from supported originals, and all wake states covered, may fact events replace part of the quiet verification. Never install an unproven native observer.

**Debt gates:** `takeover`, `easeOut`, `aimAsk`, `planeHeld`, `armSent`, `headLookHeld`, `standIn`, `on`, pending camera restoration/head/animation callbacks, session/player replacement, Core state uncertainty and any timers whose author behavior is more urgent than 0.25 s. `requested=false` or `mode=first` ALONE is explicitly insufficient. Active-to-quiet transition must execute final author reconciliation BEFORE pausing fast lane; if its completion is unproven, remain ACTIVE. Reassert/source internal timers are reviewed individually; a persistent 0.5s `reassert` countdown should not falsely keep active lane forever, but cannot be ignored without proving expected author writes.

## Registration-ownership and fallback proof

1. Source/proof gate at Resolver generation: recognized untouched or partially optimized Dedra author source, recognized composed 0-Engine stock author callback and canonical `__gcetScheduleDriver` adopted (no second CET `registerForEvent`), matching current ITP API behavior or fail-open; unknown host uses author's original source. No unproven `GetMod` from module top level.
2. On `onInit`, the **new G-CET integration** performs only pure Lua existing-scheduler job and existing event-bus subscriptions; it must not introduce any late CET `registerForEvent`, `Observe` or RTTI `Override` calls. Preserve Dedra's **pre-existing author-owned** `PlayerPuppet.OnGameAttached` `Observe` in its original `onInit` registration point, which is a separate, previously boot-tested lifecycle hook.
3. Exactly one active **execution** owner, not a new CET observer. The quiet timed job is parked while the active frame job runs; no double author steps. Every handle cancellable/unsubscribable and generation/session-safe; preserve original shutdown behavior.
4. The **runtime** must not silently lose gameplay if a supposedly installed 0-Engine host fails to expose the adopted scheduler; fail closed in Resolver when source proof is weak, and make a diagnostic/error when a once-proven dependency breaks at runtime. Do NOT attempt late native re-registration as a fallback. For supported standalone/no-0-Engine generation preserve the author's original file-load onUpdate directly.
5. Keep existing original gameplay, the previously external coordinator, user settings, camera/anim repair, and ITP missing/partially optimized behavior. No SHA-version locks or fixed mod inventory.
