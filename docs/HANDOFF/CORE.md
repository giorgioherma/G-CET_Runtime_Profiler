## Project identity

- Repository: `giorgioherma/G-CET_Runtime_Profiler`; development branch: `dev/resolver-profiler-handoff`. Always query current GitHub HEAD and the current user request.
- **Profiler:** standalone Windows GUI/CLI around a transactionally installed/restored CET native DLL. Captures callback CPU, deep source/callsite data, bursts, LuaJIT G-GC allocations/collector phases and optional CapFrameX frametimes; collects raw CSV, HTML and JSON reports.
- **Resolver:** a separate portable app that reads captured evidence plus the user's **current original/live CET mod files read-only**. Generates composable safe generic then source-proven semantic optimization overlays; does not silently edit live mods.
- One Profiler, one Resolver. The internal Resolver decision-layer codename stays **internal** and must not appear in player-facing UI, reports, releases or installer text.

## Resolver optimization architecture — mandatory ownership design

- **Generic AUTO stays cross-stack and centralized.** Generic frame dispatch, action routing/prefilters, source-proven shared-provider reads, and other mechanically safe reusable transformations belong to shared generic Resolver services. Do not duplicate global algorithms inside individual mod files or make generic eligibility depend on a named mod.
- **Semantic optimization source is organized by mod.** Each mod's authoritative source transformations are owned in `src/G.CETProfiler.Core/Services/ModPasses/<Mod>.cs`, including all related stages for that mod (e.g. GigCore, AutoLoot, ImmersiveFirstPerson). Keep the `SemanticInjectors.cs` partial-class entrypoint for dispatch and shared matching/replacement/proof helpers. Specialized external source handlers may remain separately owned when explicitly documented.
- **Separate-worker-first Lua ownership (approved):** Preserve any established G-CET-owned external Lua coordinator as external; **never fold it back inline into `init.lua`** merely because the behavior is equivalent. For substantial G-CET scheduling, cadence, dormancy, wake or lifecycle state, prefer **one mod-owned source-generated coordinator** under `GCET_Semantic/`, with a thin source-proven bridge from the author callback. Keep small generic getter replacements, source-local UI guards and author-method changes inline when extraction adds no value. 0-Engine owns shared dispatch/Scheduler APIs; each mod worker owns its own modulation/state logic; original author modules keep author behavior. No duplicate inline and external execution owners, unnecessary worker proliferation, repair-only stages or previously optimized source prerequisites. Apply generic 0-Engine → native integration → final source-aware semantics in one pass; prove worker imports, fallbacks, lifecycle cleanup, pristine generation, partial upgrades, idempotence and drift refusal.
- **Rule identity is distinct from file ownership.** Multiple measured semantic rules can legitimately map to one mod-owned file; keep their catalog IDs, evidence/admission thresholds, completion proofs, and compatibility semantics unless a separately tested change warrants merging. Group code by mod; do not blindly combine unrelated callback behavior.
- **One composed result from pristine Nexus input.** Generic and all admitted semantic stages must compose during **one Resolver generation/application pass** on untouched supported mod source. Fix the mod's authoritative implementation directly when updating an optimization; never preserve a stale pass then require a corrective pass. Generic-generated source variants and older/partially optimized sources must be recognized as compatible inputs where safely proven, or fail closed.
- **Source ownership must remain enforced.** Keep `resolver-knowledge/semantic-library.json` aligned with the dispatch table and per-mod implementation; preserve `tests/SemanticModPassOwnershipContract.ps1` and the full CI semantic/pristine/upgrade/idempotence contracts. When adding or modifying a semantic optimization, inspect *all* existing stages for that mod first to prevent duplicate work and contradictory rewrites.

See [per-mod source index](../resolver/MOD-PASS-SOURCE-INDEX.md) and [Resolver project contract](../resolver/PROJECT-CONTRACT.md). **For the active Phase 1+2 preservation-recovery task, use the [single focused engineering handoff](../resolver/PHASE12-PRESERVATION-RECOVERY.md)** alongside [LATEST-WORK](../LATEST-WORK.md); do not replace its original-source acceptance requirements with a green CI build.

## Invariants

1. Preserve source-mod gameplay, quest state, pins, UI/input, dialogue, activity, transitions, deadlines, lifecycle, cleanup and fallback. A generic/semantic pass must be version-fluid, compose with already-applied/partial changes and be idempotent. See [Resolver contract](../resolver/PROJECT-CONTRACT.md).
   - **Version-fluid is mandatory, not aspirational:** test every new source injector against the supplied **unmodified original mod archive** and the user's **currently installed/patched source**, plus at least one whitespace/comment/quote-equivalent variation. Do not gate on an exact version, SHA, line number, fixed indentation or G-CET-inserted predecessor marker. Treat independent source-proof/control-flow anchors as authoritative; reject substantive behavior drift rather than making unsafe guesses. New stages must upgrade partial passes without undoing pre-existing optimizations. **An older rule's G-CET marker proves only that older stage, never a new revision:** use distinct stage markers plus source postconditions, and test generating a new pass against an already-marked live source. Do not confuse existing v3 registration with completed v4 idle work. Add original→live→idempotent→drift CI contracts for every source-proven rule.
   - **Single-pass pristine-source contract (mandatory):** The Resolver is designed to receive mods as originally downloaded from Nexus, without any prior G-CET optimization. When correcting or extending a Resolver optimization, **fix its authoritative source implementation** rather than retaining a defective/obsolete rule and layering a corrective pass over its output. A fresh, unmodified supported mod must receive the complete current optimization in **one Resolver generation/application pass**; no historical G-CET pass or pre-existing marker may be required. A separately recognized already-optimized or partially optimized live source may still be upgraded safely and idempotently, but that compatibility path must never become a prerequisite for the pristine-source path. Test original Nexus source → complete one-pass output, plus older optimized/partial live source → complete output, repeat/idempotence and harmless formatting variants; fail closed on substantive source changes. Distinct stage markers may describe completed stages, **not** justify shipping stale source implementations or requiring sequential user passes.
   - **Version-fluid source-stage accounting:** Semantic rules with independently source-proven completed stages may emit only the still-missing changed files. The number of emitted files is **not** required to equal the total number of completed source stages. Match whitespace/quotes/comments and known equivalent generated-source forms without requiring specific historical marker or original author version. Validate completed and missing stages by source, never by a marker alone. For unknown control-flow, action interest, state lifetime, gameplay behavior or registration lifecycle changes, fail closed. No blanket regex loosening or rule-level opt-out of proof is permitted. Apply this policy across the semantic catalog as each mod's original/live/partial fixtures are proven; do not claim all mod versions supported without those tests.\n   - **Quest journal presence is not quest activation:** modded quest entries may be created or offered automatically when a mod loads, even while progression-locked or never accepted. Do not use journal-entry existence, quest mappin registration, `questArmed`/offered facts, or an installed mod as proof that expensive quest gameplay must run. Gate dormant work on source-verified *actual* activity (accepted/started stage, live scene/visit, dialogue, interaction, proximity wake, timers, pending recovery and cleanup), preserving immediate discovery and activation. Verify each mod's own state machine; never assume every mod implements identical journal behavior. See [Resolver contract](../resolver/PROJECT-CONTRACT.md).
2. A GC pause overlapping a callback does **not** establish that callback as the producer. Shared source/function names do not prove duplicate values or safe caching. Unattributed bytes remain unattributed until proven. Profiler instrumentation must be bounded, capture-gated, minimally invasive and maintain legacy measurements.
3. Native-only CI compiles the **DLL plus checksum**; main CI imports a verified pinned DLL and packages **both Profiler and Resolver**. CI tests are not in-game proof. See [build contract](BUILD-PIPELINE.md).
4. Ordinary development commits, repeated CI, documentation and experimental DLL rebuilds **do not bump product versions**. Advance both products together only upon the user's explicit request or an agreed major milestone. Identify individual builds by run ID, commit and actual native SHA.
5. Respect user's real source of truth, preserve installed mods and reversible install/restore; do not invent savings, rewrite GC policy or patch live files to obtain a result.
6. Keep `HANDOFF` small and timeless. File research and task reports in their subsystem folder and significant outcomes in [history](../history/ACTIVE-STATE.md). Documentation-only commits must not spam CI.
