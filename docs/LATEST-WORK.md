3. **Observed original Lua-side shadow interest sample (before later routing revisions):** 1,671,168 examined actions; 34,748 exact-interest hits; **0 eligible misses while wildcard interest was active 100% of the time**. In that observed source epoch, Hotscenes' permanent wildcard prevented any full-router native skip. That result is a **negative feasibility observation**, not a saved-work measurement. Hotscenes and other routing/wake changes require a *new, exact installed-source* shadow capture before updating the conclusion.
4. **Profiler evidence is available but bounded.** The normal Profiler records callback registrations, counts/rates, owner/source provenance, deep attribution, Lua-exclusive time, LuaJIT allocation pressure, bounded native boundary samples and 0-Engine source/callsite evidence where captured. Nested scheduler/0-Engine costs and owner-zero native argument-marshalling allocations must **not be counted twice or assigned to individual mods without proof**. Current baseline is the verified v1.2.9 development branch (check live `MANIFEST.json`, pinned DLL SHA and CI rather than reusing an old experimental binary).
5. **No native host suppression exists.** There is **no proven or enabled CET C++ pre-marshalling per-subscriber filter** for `PlayerPuppet::OnAction`. The standalone action-name index cannot produce performance savings if CET already constructed Lua arguments before consulting it. No controlled gameplay/FPS, GC or native-marshalling improvement has been demonstrated for this technique.

## Blocking source and safety findings

- **The original observer serves more than the ActionRouter.** User-supplied 0-Engine `init.lua` has one `Observe('PlayerPuppet','OnAction')` callback that executes `ActionRouter.Dispatch(...)` and may subsequently call **`Events.PlayerAction:trigger(action)`** when playing and outside menus. An exact-action router miss does **not** prove the *whole* observer is unnecessary. Dynamic legacy event listeners, original order and wake paths must be inspected against the **currently installed** source.
- Other mods register their own `PlayerPuppet::OnAction` callbacks or original fallbacks; no **global** OnAction suppression, native engine-method short circuit, or arbitrary callback reordering is permissible.
- In native CET source, examine the real `FunctionOverride` / `RealRunScriptFunction` subscriber dispatch and argument conversion sequence. An action CName must be read safely **before** per-observer Lua argument construction for a pre-marshalling saving to exist; a method hash, RTTI guess or Lua-side skip after conversion is insufficient. Unknown action/type, subscriber identity, snapshot, session, or observer state must **deliver the original callback**.
- Subscription interest changes (`Subscribe`, `SetActive`, `Pause`, `Resume`, `Cancel`, reload), wildcard and legacy event paths invalidate old native decisions **before** effective membership changes. Runtime delivery fails open; admission and release fail closed.
- Quest-specific dormancy and the generic static-location/RED4ext cache are **not this task**. Do not accidentally restore deferred cache code while working on native/Lua crossings.

## Next implementation and verification sequence

1. **Re-establish current source truth.** Inspect deployed 0-Engine `init.lua`, `ActionRouter.lua` and the relevant current Hotscenes/DAV/ITP source. Verify the effective active exact/wildcard subscribers and whether legacy `Events.PlayerAction` has live subscribers under driving, menus, flight and UI transitions. Preserve required offscreen/nonquest control behavior.
2. **Repeat shadow observation using the post-change stack.** Collect tagged driving/normal play with UI closed/open, including subscription changes. Distinguish `routerExactMatch`, `routerMiss`, `wildcardRequired`, `legacyRequired`, `unknown` and **wouldSkipWholeObserver**. Count observations at the real ownership level, not only generic method hashes. A callback already gated in Lua can still incur native marshalling.
3. **Inspect native CET dispatch source and prove feasibility.** Isolate experimental ASI instrumentation around `FunctionOverride` / `RealRunScriptFunction`; establish the exact 0-Engine observer registration identity, original native action-name read, whether arguments are marshalled per subscriber or once per shared invocation, and a safe pre-marshalling decision point. **Shadow only:** count potential skips, decode/lookup overhead, lost/unknown snapshots and bounded relevant allocations; **always deliver** original callbacks.
4. **GO / NO-GO.** Proceed only if a complete subscriber/legacy interest model yields material true misses, a per-subscriber native decision occurs before expensive conversion, and its cost is lower than work *actually removed*. If a wildcard remains universally live, legacy events require delivery, conversion occurs before the separable hook, or cost is unfavorable, **stop native pre-dispatch suppression** rather than layering another hot lookup onto Lua.
5. **Only on GO:** opt-in, source- and binary-pinned native suppression of **only the proven unnecessary 0-Engine observer delivery**, never the game method or other mods' observers. Keep state-change disarm, unknown fail-open and original rollback. Verify real keybinds, menus, driving, vehicle, game/world load, save, capture OFF/ON, stop/export, restore, and matched Lua CPU/native allocations/GC and CapFrameX before presenting any performance win. Profiler may be extended with bounded source/registration-scoped instrumentation as needed.
